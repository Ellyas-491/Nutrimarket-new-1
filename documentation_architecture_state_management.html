1. Apa itu Provider di Flutter?

Provider adalah pustaka resmi dan standar industri untuk State Management (pengelolaan status data) dan Dependency Injection di ekosistem Flutter.

Tujuan & Fungsi Utama:
  • Mencegah Prop Drilling: Membagikan state (seperti data keranjang, sesi user, produk) ke widget manapun tanpa harus mengoper argumen lewat constructor berkali-kali.
  • Reaktif & Efisien: Saat data dimutasi dan memanggil notifyListeners(), hanya widget yang membutuhkan data tersebut yang akan di-rebuild secara otomatis.
  • Separation of Concerns: Memisahkan logika bisnis dari antarmuka pengguna (UI) agar kode bersih, modular, dan mudah diuji.

2. Struktur Layering Arsitektur (3-Tier Architecture)

Aplikasi NutriMarket menerapkan pembagian 3 Layer arsitektur yang terstruktur secara jelas:

1. PRESENTATION LAYER (UI & Widgets)
Lokasi: lib/features/*/screens/ & widgets/
Tanggung Jawab: Menampilkan visual, animasi, form input, dan merender status (Loading, Error, Sukses). Mengirim event aksi user ke Provider.
▲ Interaksi UI • Mendengarkan State (Consumer / context.watch) ▼
2. DOMAIN / BUSINESS LOGIC LAYER (Services & Provider)
Lokasi: lib/features/*/services/ & product_repository.dart
Tanggung Jawab: Mengatur rule bisnis (kalkulasi diskon, filter nutrisi, validasi pesanan, state AI chat) dan memicu notifyListeners().
▲ CRUD & Cache • Pengambilan Data Mentah ▼
3. DATA LAYER (Data Sources & Models)
Lokasi: lib/data/ & lib/features/*/models/
Tanggung Jawab: Remote DB Supabase Cloud, Cache Offline (SharedPreferences), Secure Storage Enkripsi, dan Serialisasi Model JSON/Map.

3. Lokasi & Pendaftaran Provider di Project

Semua provider diinisialisasi secara global di root aplikasi menggunakan MultiProvider pada file lib/main.dart (Baris 67–78).

4. Siklus Interaksi UI dengan State Management

Setiap komponen antarmuka menangani 5 kondisi state utama untuk memastikan pengalaman pengguna (UX) yang responsif dan bebas bug:

1. INITIAL
Setup awal / form bersih
2. LOADING
Proses fetch / submit
3. EMPTY
Data kosong / filter 0
4. SUCCESS
Render data list / dialog
5. ERROR
Gagal jaringan / alert

5. Contoh Implementasi Nyata dari Codebase

Contoh A: State Katalog Produk (Loading, Empty, Success)

Lokasi File: lib/features/products/screens/home_screen.dart (Baris 106–157)

// 1. Membaca State dari Provider secara reaktif
final productRepo = context.watch<ProductRepository>();
final products = productRepo.products;

// 2. Kondisi LOADING: Menampilkan spinner saat pertama kali fetch
if (productRepo.isLoading && products.isEmpty)
  const Center(
    child: CircularProgressIndicator(color: AppColors.primary),
  )

// 3. Kondisi EMPTY: Menampilkan visual kosong jika tidak ada produk cocok
else if (products.isEmpty)
  Container(
    alignment: Alignment.center,
    child: Column(
      children: [
        Icon(Icons.inventory_2_outlined, size: 48),
        Text('Belum ada produk di kategori ini'),
      ],
    ),
  )

// 4. Kondisi SUCCESS: Merender grid produk aktif
else
  GridView.builder(
    itemCount: products.length,
    itemBuilder: (context, index) => FoodCard(product: products[index]),
  );

Contoh B: State Aksi Form, Loading & Error Handling

Lokasi File: lib/features/auth/screens/login_screen.dart (Baris 72–195)

// Step 1: Set state ke Loading saat tombol ditekan
setState(() => _isLoading = true);

try {
  // Step 2: Hubungi Domain / Logic Layer
  final supabaseService = Provider.of<SupabaseService>(context, listen: false);
  final response = await supabaseService.signIn(email: email, password: password);

  // Step 3: Kondisi SUCCESS -> Tampilkan Notifikasi & Navigasi
  AppToast.show(context, title: 'Berhasil Masuk', type: ToastType.success);
  Navigator.pushReplacementNamed(context, '/home');
} catch (e) {
  // Step 4: Kondisi ERROR -> Tangkap Exception & Berikan Feedback ke User
  AppToast.show(
    context,
    title: 'Gagal Masuk',
    subtitle: 'Email atau kata sandi tidak sesuai.',
    type: ToastType.error,
  );
} finally {
  // Reset indikator loading
  if (mounted) setState(() => _isLoading = false);
}
